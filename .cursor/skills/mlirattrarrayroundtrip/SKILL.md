# Attribute with an array parameter does not round-trip

## Symptom

    loc("ir_in.mlir":8:158): error: expected integer value
    error: failed to parse KernelBlockAttr parameter 'tensor_shape' which is to be a `::llvm::ArrayRef<int64_t>`
    [TilingLinalg] ERROR: AIEHLC_DMAPHOP_IR_IN: ir_in.mlir does not parse / verify

The normal build is fine; only feeding a dumped IR back in fails
(`script/test/routing_ir_roundtrip.sh`, `RoutingIR.check()`, any re-entry).

## Cause

`let assemblyFormat = "`<` struct(params) `>`";` prints an
`ArrayRefParameter<"int64_t">` as a bare comma list:

    #routing.kernel_block<tensor_shape = 64, 256, shape = 16, 64, ...>

The parser of that list keeps going after each comma, so `shape` is read as the
next integer of `tensor_shape`. `struct(params)` is only safe when no parameter
is an unbracketed list (scalars, nested attrs, `OptionalArrayRefParameter` of
attributes are fine).

## Fix

Write the format out and bracket each array, and print every field
(`src/mlir/mlirfront/tilinglinalg/routing/td/routingattr.td`, `KernelBlockAttr`):

    `<` `tensor_shape` `=` `[` $tensor_shape `]` `,` `shape` `=` `[` $shape `]` `,` ...
    `,` `resident` `=` $resident `,` `tile_r` `=` $tile_r `,` `tile_c` `=` $tile_c `>`

Second trap: do NOT make the defaulted params optional groups that each start
with a comma -- `(`,` `resident` ...)? (`,` `tile_r` ...)?` prints
`..., tile_r = 8, tile_c = 8>` and the parser, having seen `,`, commits to the
first group: `error: expected 'resident'`.

Third trap: a `DefaultValuedParameter` prints **nothing** when it holds its
default, even written as plain `` `resident` `=` $resident `` -- the dump reads
`resident =, tile_r =, tile_c =>` and fails with `failed to parse ... parameter
'resident' which is to be a bool`. Printed-always fields must be plain
`"bool"` / `"int64_t"` parameters.

The `.inc` files are regenerated by the build (`routing/gen.sh` from CMake);
editing the `.td` and `make` is enough.

## Check

    bash script/test/routing_ir_roundtrip.sh --stage routing example/tileprogram/ccode/simplegemm_dataflow.cc
    bash script/test/routing_ir_roundtrip.sh --stage dmaphop example/tileprogram/ccode/simplegemm_kernel_port.cc

Both must say `[roundtrip] PASS`. Any new attribute with an array parameter
should be added to a round trip that exercises it -- a normal build never parses
its own output, so the bug is invisible there.
