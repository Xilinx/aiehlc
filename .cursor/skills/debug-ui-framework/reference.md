# Debug UI Framework — Reference

Implementation notes for `schedule_debug_server.py`, `schedule_view.py`, and
related debug tools.

---

## Embedded LLM plugin (dbg-llm-skills)

Ten verified procedures for **live AIE debug**, written for the *embedded*
assistant in the browser debug UI's LLM tab but equally usable by a local session.
Laid out as a Claude Code plugin (`.claude-plugin/plugin.json` +
`skills/<name>/SKILL.md`), which `schedule_debug_server.py` loads by passing
`--plugin-dir` to its `claude -p` spawn — one copy, versioned beside the tooling
it documents, rather than a duplicate under `.cursor/skills/` that would drift.

The ten skills:

| Skill | Purpose |
|-------|---------|
| `session-provenance` | Four session states; read before quoting registers or logs |
| `aiegdb-console` | `aie_exec` command surface from `aiegdb.COMMAND_SPEC` |
| `debugui-tools` | Granted `mcp__debugui__*` tools (incl. `get_live_scan`) |
| `live-scan-results` | Interpret DMA/Cores/Events/Switch overlay scans |
| `dma-stall-triage` | Producer→hop→consumer decision tree |
| `app-layout` | Which file answers which question; bundle vs app root |
| `simulator-vs-hardware` | Two backends, two read paths, two log sets |
| `aiedbg-reference` | Index into the aiedbg clone |
| `root-cause-workflow` | UI observation → root cause reasoning |
| `source-grounding` | When to leave registers for app source; `<file>:<line>` form |

**Live scan → LLM:** `GET /grid?what=…` records via `DebugState.record_live_scan()`,
writes `backend_status.json > last_scan`, attaches `llm_summary` to the JSON
response, and the browser calls `llmPushCtx(..., 'scan')` in `applyGrid()`.
On-demand: `mcp__debugui__get_live_scan` (also `GET /live_scan`). Summaries live in
`live_scan_summary.py`.

Local use: `claude --plugin-dir src/tool/debug/dbg_llm_skills`, or Read the file
directly. `src/tool/debug/dbg_llm_skills/README.md` documents front-matter and
discovery (`_llm_skills()` scans at prompt-build time).

## External: aiedbg clone

Path: `/scratch/staff/bkirinci/aiedbg`, installed as `aiedbg` on PATH.

This repo's `aiegdb.py` shells out to `aiedbg -d <device>` for raw passthrough;
`aiediag.py` reimplements its register decoding. ~2600 lines of docs live **only
in the clone** — note `import aiedbg` resolves to the installed *non-editable*
copy in site-packages, which has no `.md` files.

Covers TCP-vs-XSDB backend split (VEK385 is XSDB-only), legacy/enhanced device
matrix, named-register lookup. **`reg lookup` runs offline** (no board) and is
the authority when `aiediag`'s decode is in doubt — but on this install
`aiedbg -d pal reg lookup …` crashes with `AttributeError: device_type`; spell it
`--device-type pal`. Indexed by the `aiedbg-reference` plugin skill.

## aiediag.py

Flow-aware DMA diagnostic: reads DMA status registers via `aiedbg`, cross-references
provenance map JSONs (`dfscheduleprovenancemap.json`, `dmaphopprovenacemap.json`)
and shim event status (`~/aiejson/shimtile_events.json`), identifies connected
tiles and routing paths, prints automated root-cause diagnosis for DMA stalls.
See `README.md > Debug Tools` for full usage.

**Pitfall:** offset-as-value parsing — false BD_UNAVAIL/BD_INVALID from decoding
the register *offset* `0x1DF10` instead of the *value*. Always confirm with
`aiedbg reg read`.

## xaiehost2provenance.py

Static provenance generator for the **raw-XAie single-kernel** aiehlc flow (emits
`main.elf` + `host.cc` but no tilinglinalg `worklocal/` bundle — the
`not found: aout/worklocal/host_schedule.html` error).

Regex-parses generated `aout/host.cc` XAie calls — `XAie_LoadElfMem` (kernel
placement), `XAie_MoveDataExternal2Aie` → S2MM, `XAie_MoveDataAie2External` →
MM2S, `XAie_Route` (connectivity) — into the schema `schedule_view.py` consumes.

It also recognizes **control-packet routing** (`__Runtime_CtrlInstance` /
`__Runtime_ctrl_setup_routing` / `__Runtime_ctrl_read_target` /
`__Runtime_ctrl_push_target`): each same-column send `(shim_col, dest_row,
resp_words)` emits the shim tile, the vertical pass-through tiles, and the dest
tile (geometry-aware: shim / memtile / core by `AIE_GEN`), plus two flows —
forward S2MM up (shim→dest) and return MM2S down (dest→shim). No kernel ELF ⇒
`kernel_placements` stays empty. This lets `schedule_debug_server.py` open a
debug GUI for a control-packet app that has only `host.cc` (no `Work/` tree).

- `MacroResolver` selects live `#if/#ifdef` branch for `AIE_GEN`/`__AIESIM__`
  and honors inline `#define`/`#undef` (so an in-file `#define _CONTROL_WRITE_TEST_`
  guard followed by `#ifdef` keeps its block)
- `strip_comments()` drops inline `/*src=*/` notes that break tile-loc regexes
- Runtime BD/lock/port/packet → placeholders (`bd_id:"runtime"`, lock id `-1`)
- Entry function `test_routing` (not `host_canonicalized`) → `host_entry_fn`

Wired **non-fatally** into `aiehlc.sh` after host build. CLI:
`xaiehost2provenance.py <host.cc> --out-dir <dir> --aie-version <N> [--platform baremetal|sim]`.
Tests: `src/tool/debug/tests/test_xaiehost2provenance.py`.

## aiegdb.py

GDB-like scoped CLI over `aiedbg`. Stateful REPL: partition → tile → channel.
`target tile 0 0` / `target channel mm2s0` change prompt/breadcrumb.

- Tile scope auto-injects `phys_col=col+startcol`, `row`
- Channel scope auto-injects `dir/ch`
- Helpers: `dma status`, `bd`, `event`, `dma counter`
- Read-only by default; only write is explicit `dma counter setup`
- `--dry-run`, `-c "cmd"`, `--script FILE`

**`COMMAND_SPEC`** is the machine-readable grammar (module dict keyed
`universal`/`partition`/`tile`/`channel`). `_commands()` renders from spec;
browser autocomplete reads `/aiegdb/spec`. Format:
`f"  {sig:<36}  {summary}"` — two trailing spaces are load-bearing for browser split.

## aiemcp.py

MCP server exposing `aiegdb` to Claude Code. Third front-end on `AieGdb.run_line`
(browser/daemon is the other). ONE long-lived in-process instance preserves scope.

Tools: `aie_exec`, `aie_scope`, `aie_commands`, `aie_help`.

- `_run()` uses OS-fd-level `dup2` capture (FastMCP stdio uses fd 1 for JSON-RPC)
- Config via env / `.mcp.json`: `AIEDBG_TARGET`, `AIEMCP_DEVICE/STARTCOL/…`
- **Session gate:** `_session_refusal()` before device access; navigation/help allowed
- LLM-tab: daemon writes temp `.mcp.json` with resolved HW config for `_llm_spawn`

Smoke test: `AIEMCP_DRY_RUN=1 mcp dev src/tool/debug/aiemcp.py`.

## schedule_debug_server.py — session provenance

`self.target` at startup (`--target` → `$AIEDBG_TARGET` → `~/.aiedbg_env`) proves
nothing about whether this session reached the board.

Four states via `session_state()` / `session_summary()`:

- `none` → `connected` (`/ping`) → `attached` (`POST /attach`) → `ran` (`start_run`)

`hw_authorized()` gates `/grid`; aiegdb console stays ungated. `applog_provenance()`
classifies applog as `current`/`predates_session`/`foreign`/`absent` by mtime.

Published in `backend_status.json` and injected into every LLM message via
`_llm_backend_context()`.

**App location:** `app_paths()` resolves `app_dir`, `bundle_dir` (`worklocal`),
`work_dir` (`Work/`), `elf`. Per-message copy is load-bearing when `select_app()`
swaps mid-conversation.

## schedule_debug_server.py — app capability detection

Startup listing tags each app `sim`/`hw`/`sim,hw`/`view-only` (what the daemon
can find, not a restriction).

Simulators detected from build artifacts via `_detect_sim_device()`:

- aiehlc: `sim_config.sh` → `script/runsim.sh` (`sim_kind='aiesim'`)
- naiebaremetal: `ipc/build_sim.env` + `Work/ps/c_rts/systemC` → `runsim_ipc.sh` (`sim_kind='ipc'`)

Hardware via `_detect_vek385_device()`: needs `<example>/build/vek385.BIN`.

**Board never baked into profile:** `_board_run_env()` resolves at launch from
UI box → `$VEK385IP` → `hwlocal.sh`. `_BOARD_KEYS` dropped from declared
`hw_env` on overlay. `_device_label()` strips stale host from profile labels.

`App._no_sim_reason()` names missing artifacts for surviving `view-only` apps.

## schedule_debug_server.py + schedule_view.py — run-state reconciliation

Browser previously learned runs only from its own `/applog` tail after **Run test**.
Page reload / external run left UI out of sync with daemon.

Fixes:

1. **`GET /runstate`** — polled every 5s; `applyRunState()` edge-triggered on `running`
2. **`busy:true`** on mid-run refusals (`/ping`, `/attach`, `/settarget`, `/run`)
3. **`stop_run()`** clears `_run_proc` unconditionally (uninterruptible child trap)

`updateRunButtons()` gates Force stop on `LIVE.runOwned` alone, not `LIVE.connected`.

## schedule_debug_server.py + debug_ui_mcp.py — source grounding

Three layers: live registers, compiled schedule, application source.

`_app_source_manifest()` walks `app_dir`, groups Entry/Kernels/Application/Headers/Build/Generated.
`_app_kernel_defs()` maps tile kernel names to source lines. aiehlc flow uses
`worklocal/app_source.txt` from `aiehlc.sh`.

Published: system prompt, `backend_status.json > app_sources`, `mcp__debugui__app_sources()`.

Citation gotcha: use inventory path form, not bare basename — bare `stream_accum.cc`
opens bundle copy; `src/stream_accum.cc` opens the editable file.

## schedule_debug_server.py + schedule_view.py — sim-only

`--sim-only` hides board row, Connect, Attach; auto `testConnect()` on load.
`_refuse_sim_only()` blocks hw endpoints with `sim_only: true`. `/grid`, `/cmd`,
`/aiegdb` still work for IPC simulator live reads.

Run pane renamed **Execution** (was Run). Single app → hide App dropdown.

## schedule_debug_server.py + schedule_view.py — single-app daemon

When invocation names an app (positional workdir or `--app`) without `--app-root`,
skip auto-scan of `aout/` and `example/`. Positional `workdir` default is `None`
(not `aout/worklocal`) so bare vs explicit is distinguishable.

## schedule_view.py — browser UI features

### aiegdb console tab

Foldable `.con-blk` per command; `CON_RULES` regex classifier; register appendix
in `<details>`. Autocomplete from `CON.spec` (`GDBSPEC_STATIC` + `/aiegdb/spec`).
Newest-first history: current `.con-blk.cur` expanded below input.

### LLM tab

- **Context channels:** `LLM.ctx`/`ctxSent` are Maps keyed by `session`/`run`/`search`/`selection`
- **Inline context pills:** contenteditable `#llmin` (not textarea); ZWSP caret scaffolding
- **Tool-call rendering:** `.llm-tools` blocks with chip args; FIFO pairing
- **Working indicator:** driven by `/llm/poll` `active` flag, not first data chunk
- **Bottom pinning:** `llmKeepBottom()` on sibling height changes

### One device namespace

`st.device` = aiedbg `-d` flag. Dropdown uses `DEVICE_CONFIGS` names; `resolve_device()`
unifies with board selection. Fixes 12-column `pal` vs 38-column `vek385` scan bug.

### Source viewer

`GET /source?path=&line=` — Pygments JSON; scoped under `.srcview`. Two-tier path
index; `linespans='SL'` for line-independent cache. Auth-gated on wide bind.

### Device map

- **Flow lanes:** `flowLane(fi)` — one lane per flow for whole path continuity
- **Whole-flow hover:** `dmApplyFlowHover(fi)` highlights all segments + shmem for flow index
- **Tile colors:** muted `--tile-*-fill/stroke` (Grid keeps original `--shim`/`--core`)
- **Routing-only tiles:** `selectRoutingTile()` / `buildRoutingTileHtml()`

### Grid view

- Original saturated tile colors unchanged
- **Scan controls:** mode pills don't auto-start live; `#gridScanBtn` added
- **Click-to-target:** `setConTargetLoc` works without schedule match or Connect gate

### Info pane

- **Capabilities:** `{host_lines, ir, kernel_code}` — baremetal omits IR tab
- **Code file tabs:** Default / host.cc / Kernel files rail
- **Pane names:** AIE Debug, Execution, Info, Tools (published to LLM prompt + MCP)

### Execution log tail

`logFollowing()` / `logFollow()` — slack `max(160px, 0.5 × clientHeight)` not 4px.

- **[src/tool/debug/schedule_view.py](src/tool/debug/schedule_view.py) — LLM tool-call rendering** — The daemon emits tool activity as line markers wrapped in blank lines (`\n[tool: <name> <args>]\n`, `\n[tool result: …]\n`) and `.llm-msg` is `white-space:pre-wrap`, so each call cost three lines, its result three more, long args wrapped further, and the result never paired with its call. `llmProse()` now collapses a run of those markers (blank lines included, leading blanks popped off `outLines`) into one `.llm-tools` block holding one `.llm-tc` flex row per call: `.tn` name via `llmToolName()` — strips the `mcp__<server>__` prefix, splits `snake_case`+`CamelCase`, sentence-cases and upper-cases known acronyms from `LLM_ACRONYM` (`aie_exec`→`AIE exec`, `get_ui_state`→`Get UI state`), rendered in the sans stack while values stay monospace; `.ta` args via `llmToolArgs()` — JSON-parsed into one background-filled `.tg` chip per key (label + value side by side, values >60 chars ellipsised, raw-text fallback when the parse fails, no chip border since it would grow the row); and `.tr` folding the result onto the same row (`✓ 41 lines` / `✗ error` / `…` in flight); the left border is grey→accent→red by state and `white-space:normal` on the block escapes the bubble's pre-wrap. `_llm_handle_event` supplies the tag not the payload — `len(result_text.splitlines())`, `empty`, or `error` from the tool_result block's `is_error` — because results run to register dumps. **Pairing is FIFO**: Claude issues tools in parallel batches, so the stream is N calls back to back then N results, never strict alternation (confirmed in `llm_*.log`: two `TOOL CALL` lines, one `TOOL RESULT`, two more calls, then three results). Filling the LAST unresolved row left every earlier call stuck on `…` and the surplus results orphaned into nameless rows that rendered as a tool literally named "Tool"; each result now fills the FIRST unresolved call, and a result with no open call (its call split into an earlier block by prose) renders as a `↳` continuation row. - **[src/tool/debug/schedule_view.py](src/tool/debug/schedule_view.py) — context pills placed inline** — "+ Add context" parked every selection in a row above the input and prepended them all on send, so the blocks vanished from the transcript once drained and there was no way to say *where* a snippet belonged. The prompt box is now a **`contenteditable` div, not a `<textarea>`** — a textarea cannot hold elements — and the pills are real chips inline in the message at the caret; the separate `#llm-ctx-pills` row is gone. Each chip is `contenteditable="false"`, carries `data-cid` into `ctxSnippets`, and has an `×`. Chips **select/copy/cut/paste like text**: only `.mp-x` keeps `user-select:none`, `copy`/`cut` write both a plain-text flavour through the shared walker (`[[label]]`, never the `×` glyph or the ZWSP scaffolding) and an HTML flavour so pasting back rebuilds a real chip, and `paste` reconstructs chips from `data-cid` while turning **everything else into plain text** — parsed with `DOMParser` (inert document) not `innerHTML`, so a pasted `<img onerror>` neither loads nor fires; a chip whose snippet is gone degrades to its `[[label]]`. Newlines on paste are the fiddly part because a copy out of a contenteditable comes back wrapped: a break is emitted BEFORE a block and never after (one after each block added a trailing blank line per wrapper), and a chip is inline text that must never start or end a line of its own — `dropNl()` removes a break the wrapper put immediately before a chip and `justPill` swallows the one that follows, while an explicit `<br>` is user intent and always stands. Three things make the caret behave: (1) a `selectionchange` listener remembers the last range inside `#llmin`, because selecting text in another pane moves the document selection out of the box, so at click time there is no live caret — this is why chips used to land at the end regardless of where you were typing; (2) chips are flanked by **zero-width spaces** so the caret has a text position on both sides (without them the browser cannot place a caret before a leading chip or between two adjacent ones), stripped by the reader; (3) Backspace/Delete are intercepted so a chip goes in ONE press — the browser would eat the flanking ZWSP first and the press would look like a no-op — with only that ZWSP counting as "nothing in between", so a space the user typed is deleted first. `ctxReadInput(pill)` is the one walker that reads the box back, the `pill` callback deciding what a chip becomes — the full `[context from …]` block for the outgoing prompt, `[[label]]` for the transcript echo and the has-anything-to-send check — normalising `<br>`/browser-made blocks to newlines and the post-chip `&nbsp;` back to a space. Switching the tag sprang a trap worth remembering: the device map's capture-phase Space handler (page-scroll suppression) exempted typeable focus **by tag name** (`INPUT`/`TEXTAREA`), so once the prompt box became a `div` every space typed into it was eaten — and only in Device Map view, the default. It now also tests `ae.isContentEditable`. The editable box needs three things a textarea gave free: Enter intercepted to send with **Shift+Enter** via `insertLineBreak` (the browser otherwise builds `<div>` soup), **paste forced to plain text** (default pastes markup, so copying from the transcript injects spans), and no `autoGrow` — it self-sizes, with an `input` listener re-pinning via `llmKeepBottom`. `llmSend(prompt, fromInput)` gained the flag because the box is the source of truth: only an interactive send drains it, so a programmatic caller cannot drain a half-written message. The **auto DMA-scan alert is gone** — `_updateIssueBar` used to fingerprint the issue set (`_issueAlertSent`) and auto-send `[auto] DMA scan detected N issues…` while switching to the LLM tab unprompted; it now only renders the issue bar, and asking the model is the user's call. Labels are deliberately no longer renumbered on delete — collapsing `#1/#2` back to bare is fine for a chip but would orphan a token already sitting in the user's message, which is why `ctxDisplayLabels()` was retired. `llmAddSentCtx()` echoes what went out as read-only pills above the `you` bubble (`.llm-msg-sctx`), click-to-expand the exact text; the prompt is echoed with tokens intact so the expanded blocks don't bury the question.
