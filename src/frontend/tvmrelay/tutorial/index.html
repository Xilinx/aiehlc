From an ONNX model to a ResNet-18 layer running on the AIE

A developer walkthrough of src/frontend/tvmrelay/: how ResNet-18 is downloaded, imported into TVM, quantized to int8, compiled to C, split into layers, how layer 01 (the 7×7/s2 stem convolution) is handed to the AIE as src/aietensorop/conv2dstem/conv2dstem.cc, and how that is wired into graph_driver.c and linked into the board's main.elf. Written so you can debug it, speed it up, or rebuild any piece by hand.

Verified state this tutorial describes (2026-10-09) run_test.sh passes; on the board, layer 01 runs on the AIE ([aie-offload] layer 01 … EXIT rc=0 … hash=2aeeab65), the AIE output is bit-exact with TVM's own layer-01 output over all 802,816 bytes, and the top-5 is identical to the CPU-only main_local.elf: 258 Samoyed 12.0173, 279 Arctic fox 8.5263, 259 Pomeranian 8.1906, 257 Great Pyrenees 7.9220, 270 white wolf 7.4521.

Two ideas hold the whole thing together:

  1. TVM owns the network, the AIE owns one operator. TVM compiles all 41 kernel calls to portable C. The offload replaces one call — the stem conv — with a function that has the exact same signature but runs on the AIE. Nothing else in the graph knows.
  2. The same C builds two ELFs. main.elf (board, AIE) and main_local.elf (x86, CPU only) come from the same graph_driver.c; the only difference is the macro GRAPH_AIE_OFFLOAD. So the CPU ELF is always the reference the board must match.

4. relay.build → C

deploy_flow.build_c calls relay.build(mod, target=pe_target, params) with target_host="c" and collects the C. Inside the build, the passes that decide what your layers look like:

  • Legalize (int8 rule from pe_target) and qnn CanonicalizeOps: qnn.conv2d becomes nn.conv2d + explicit zero-point / requantize integer math.
  • AlterOpLayout: nn.conv2d becomes nn.contrib_conv2d_NCHWc; tensors become 5-D [N, C/c, H, W, c]. That is why layer 01's output is uint8[1,16,112,112,4].
  • FuseOps: groups ops into one C function each. Layer 01's function name spells out its fused body: tvmgen_default_fused_nn_contrib_conv2d_NCHWc_subtract_add_subtract_fixed_point_multiply_per_axi_1a1eefcf0256215e_.

Output: resnet18.c (33 kernel functions), resnet18_graph.json (41 calls, which storage id each tensor lives in, every shape and dtype), resnet18_params.bin.

Every kernel uses TVM's packed-call ABI — remember it, the AIE entry in §10 copies it:

int32_t fn(void* args,            /* TVMValue[]: .v_handle = DLTensor*       */
           int32_t* arg_type_ids, /* 7 = kTVMDLTensorHandle                 */
           int32_t num_args,      /* inputs then outputs; layer 01 has 8 + 1 */
           void* out_ret_value, int32_t* out_ret_tcode, void* resource_handle);

5. Split into layers/

split_layers.py cuts resnet18.c into one translation unit per kernel — layers/NN_<ops>/NN_<ops>.c — in first-use order, plus layers_common.h (the shared prologue) and manifest.json. Editing one operator recompiles one file.

Three different things are all called "layer 01" (1) the call index in the graph ([01] in a trace, # in network.md), (2) the folder prefix 01_ (distinct kernels; a kernel called twice has one folder), (3) the --aie-layers number (= the folder index). For the stem all three are 1; further down the network they diverge. The manifest maps folder → symbol; the graph maps symbol → call nodes.

6. Picking the layer: --aie-layers 1

aie_offload.resolve_conv_targets turns "layer 1" into an identity that survives graph rewrites:

  1. manifest entry 1 → symbol → the graph node calling it (by symbol, not position — a kernel called twice would shift every later layer by one);
  2. geometry from the graph's shapes, folding NCHWc back to channels: [1,1,230,230,3] → [64,…] gives 230×230×3 → 64ch K7 s2 (aie_offload._layer_geometry; skill nchwclayoutfold);
  3. the weight fingerprint: the conv's weights sorted, cast to int64, hashed (byoc.aie_annotate.weight_fingerprint). Layout- and dtype-independent, unique for all 20 convs — this is how the pre-build Relay conv and the post-build graph node are matched.

7. BYOC: fuse, select, partition, codegen

This is TVM's "Bring Your Own Codegen" path, in byoc/. It runs on the pre-build Relay module (before AlterOpLayout makes convs 5-D), carves the selected conv out into a function marked Compiler="aie", and lets relay.build call our codegen for it. aie_byoc.partition_for_aie drives four steps, one file each:

#filedoes
1 fuseaie_fuse.fuse_layersInferType → FoldConstant → qnn.CanonicalizeOps → FoldConstant → MergeComposite(pattern_table()); each match becomes a function with attribute Composite="aie.qconv_fused", tagged aie.weight_fp
2 selectaie_annotate.ConvSelectAnnotatorkeep a composite if its fingerprint is selected and kernel_can_run says yes; wrap it in compiler_begin/end("aie"); inline everything else back
3 partitionaie_byocMergeCompilerRegions → PartitionGraph: the region becomes a global function tvmgen_default_aie_main_0
4 codegenaie_codegen (relay.ext.aie)during the second relay.build, emit C for that function: a wrapper calling conv2d_stem_prepadded() in aout/libconv2dstem.a

7.1 What a "composite" is — the multi-op layer as one unit

The AIE kernel computes conv + bias + zero-point + per-channel requantize + clip + uint8 store in one pass and can produce nothing else, so the unit handed over must be that whole chain, not the bare conv. aie_patterns.fused_qconv_pattern() describes it with Relay's dataflow pattern language:

conv  = nn.conv2d(x, CONST)
acc   = subtract(conv, multiply(CONST, repeat(avg_pool2d(multiply(sum(cast(x)), CONST)))))  | conv
acc   = add(acc, CONST)                    # C2   ← required
acc   = nn.bias_add(acc, CONST)            # C3
acc   = cast(acc) | acc
acc   = subtract(acc, CONST)               # C4
acc   = fixed_point_multiply_per_axis(acc, CONST, CONST, CONST)   # C5 mult, C6 lshift, C7 rshift
root  = cast(clip(acc))                    # uint8

MergeComposite replaces every subgraph matching this with a call to a small function holding those ops. extract_fused() then walks it from the final cast down and names each constant — it is the single place that decides "what C2 means", used by both the checker and the codegen.

7.2 Two gates: shape, then capability

  • check_fused_qconv (MergeComposite's check): is it well-formed? Shape only.
  • kernel_can_run (step 2): can libconv2dstem.a reproduce it bit-exactly? Exact STEM_GEOMETRY (230×230×3 → 64, 7×7/2, no padding — TVM hoisted it into nn.pad), zero weight zero-point, right-shift only, clip [0,255]. Returns (ok, reason).

deploy_flow reports the two outcomes differently: did not fuse (info["unmatched"]) vs fused but rejected, because … (info["rejected"]).

7.3 Folding the epilogue into the kernel's four numbers

The kernel reads, per output channel, {bias, zp, mult, shift} and computes v = (int64(acc + bias − zp) · mult + 2^(sh+30)) >> (sh+31), then clamps to [0,255]. aie_codegen.fold_qparams maps the composite onto that: bias = C2 + C3 − C4 + 128·Σw, zp = 0, mult = C5, shift = C7. The +128·Σw is because the uint8 input (zp 113) is passed to the int8 kernel as x − 128; a plain reinterpret corrupts every pixel ≥ 128.

7.4 "Fuse" means two things — do not reorder them

Step 1's MergeComposite groups ops for the AIE. TVM's FuseOps is the last pass of the second relay.build and fuses whatever stayed on the CPU. BYOC must come first so FuseOps never fuses across the AIE boundary.

7.5 Why BYOC fuses 0 of 20 convs today known gap

Every --aie-offload run prints:

[aie-byoc] 1/4 fuse  : nothing (AIE_BYOC_DEBUG=1 prints every non-match)
[aie-byoc] 2/4 select: annotated 0 aie.qconv_fused for AIE (1 conv(s) selected; 0/20 convs fused)
[aie] layer 01: does not match any AIE pattern -- stays on the APU

and AIE_BYOC_DEBUG=1 prints no rejection — the checker is never even called, so the pattern's structure does not match. Dumping the canonicalized stem with today's defaults shows why:

%6  = nn.conv2d(%5, W:int8[64,3,7,7], strides=[2,2], …)
%7  = subtract(%6, C:int32[1,64,1,1])          ← one constant subtract, no add
%8  = nn.bias_add(%7, C3:int32[64])
%9  = cast(%8, int32)
%10 = subtract(%9, C4:int32[64,1,1])
%11 = fixed_point_multiply_per_axis(%10, C5, C6, C7, is_rshift_required=True)
%13 = cast(clip(%11, 0, 255), uint8)

The pattern was written against the IR before the qnn zero-point fold (§3) became the default. Then, the kernel zero-point was a per-channel tensor, and canonicalization produced subtract(conv, multiply(C1, window_sum)) … add(C2). With the fold, the kernel zero-point is a scalar 0, the window-sum term disappears, and the input-zero-point term (113·Σw) becomes a constant subtract. The pattern's mandatory add(acc, CONST) has nothing to match.

Checked (2026-10-10): turn the fold off and the same pattern fuses. Without the fold the graph renumbers (64 layers; the stem is layer 6), so:

AIE_BYOC_DEBUG=1 PYTHONPATH=src python3 src/frontend/tvmrelay/deploy_flow.py \
    --aie-offload --aie-layers 6 --no-fold-qnn-zp --no-arm --out-dir /tmp/byocnofold

[aie-byoc] fused qconv: {'in_hw': (230, 230), 'in_c': 3, 'kernel': (7, 7), 'strides': (2, 2), …, 'out_c': 64}
…   (8 more 3×3 convs)
[aie-byoc] 1/4 fuse  : aie.qconv_fused x9
[aie-byoc] 2/4 select: annotated 1 aie.qconv_fused for AIE (1 conv(s) selected; 9/20 convs fused)
[aie-byoc] 3/4 part  : 1 AIE subgraph(s): tvmgen_default_aie_main_0
[6/7]          rebuilding the C with 1 AIE subgraph(s) (calls conv2d_stem_prepadded() in aout/libconv2dstem.a)

So the BYOC machinery works; the pattern is out of date for the default IR. Two side effects of that configuration worth knowing: the BYOC wrapper is compiled into the kernel C, so make local refuses to build, and the extra aiegraph lift fails verification on the unfolded graph (two adds in a conv's name are read as a residual) — it is reported as aiegraph lift failed, no aie/ built and the run continues.

Fix direction (not done): make the add optional and accept subtract(conv, CONST) as its negation in the pattern, and have extract_fused map it into C2 with the sign flipped. Then verify_aie_stem.py is the gate (0/802,816 mismatches, 0/1000 logits). Until then the offload goes through §8.

8. The aiegraph path — what actually runs layer 01 today

--aie-offload also runs aiegraph_partition.run_aiegraph over the same --aie-layers selection. It never rewrites TVM's C — it adds AIE artifacts beside a layer:

  1. Lift every graph node to an aiegraph op (build_nodes): a layer whose fused op list contains conv2d becomes conv_bn (or conv_bn_relu), with geometry from the graph JSON — 5-D NCHWc folded via aie_offload._layer_geometry. Written to layers/aiegraph.mlir, verified by the dialect: 
    %0 = aiegraph.conv_bn %arg0 : tensor<158700xi8> {Cin = 3, Cout = 64, H = 230, W = 230,
       K = 7, stride = 2, weights = @w9, …} -> tensor<846400xi8>
  2. Partition (partition_layers): layers in --aie-layers whose ops are all offloadable go target: aie; everything else cpu, each with a reason → layers/partition.json.
  3. Build each AIE layer (_build_one). If its geometry is exactly the stem (aie_stem_lib.matches_stem, against STEM_GEOMETRY), it is built from the hand-written conv2dstem.cc (§9). Otherwise the generic run_aie_pipeline + kernels.conv_bn_body placeholder is used — int16 accumulator, dummy quant: right shape, not TVM's arithmetic.

The verdict for layer 01 in partition.json:

{ "index": 1, "target": "aie", "aiegraph": ["conv_bn"],
  "backend": "aiehlc", "source": "src/aietensorop/conv2dstem/conv2dstem.cc",

9. conv2dstem.cc → the layer's aie/

9.1 What conv2dstem.cc is

An aiehlc source holding both the AIE kernel and the host code around it:

  • __global__(conv_policy) void conv2d_spatial(…) — the core kernel: int32 accumulate over a 7×7×4 window, then (sum·mult + 2^(sh+30)) >> (sh+31), clip, uint8. The per-channel {bias, zp, mult, shift} ride in the weight row's pad channel (channel 3 of INPUT_C_ALIGN = 4).
  • Viewed as a GEMM: M = 112·112 = 12544 output pixels, N = 64 filters, K = 7·7·4 = 196, spread over a 4×4 mesh of core tiles (HW_ROWS/HW_COLS) with three aie::GemmSpace descriptors (row broadcast of the input halo, column broadcast of weights, left-to-right merge of outputs). static_asserts pin the tiling to the geometry.
  • Host side: ensure_staging (DMA-capable buffers), stage_ifm_prepadded (230×230×3 → ×4 channel-aligned), stage_weights_nchwc (OIHW3i4o → BT[64,196] with qparams in the pad channel), launch conv2d_spatial<<<mesh>>>, collect_ofm_nchwc (HWC → NCHW4c).
  • Three public entries, same math, different layout: conv2d_stem (raw input), conv2d_stem_prepadded (BYOC, HWC), conv2d_stem_nchwc (TVM's packed layouts — used here).

test_conv2d.cc is the same file plus a main(): it reads TVM's real layer-01 inputs (a make TRACE=1 dump), calls conv2d_stem_nchwc and checks all 802,816 outputs (GOLDEN PASS 802816/802816).

9.2 How it gets built into the layer

aie_stem_lib.build_stem_layer:

scratch=$(mktemp -d); cd $scratch            # aiehlc writes aout/ relative to the CWD
source script/aiehlc.sh --aie-version 5 \
    --runtime-source-file src/aietensorop/conv2dstem/conv2dstem.cc
# no main() → library mode: aout/worklocal/{host.cc, kernel.cc, conv2d_spatial.cc,
#                                            routing.cc, aieml.bcf/.prx, build/libconv2dstem.a}
cp -r aout/worklocal  layers/01_…/aie        # minus the 6 MB layeriohex data headers

aiehlc does the hard part: the Clang frontend extracts the __global__ kernel into conv2d_spatial.cc/kernel.cc (compiled for the core with xchesscc), lowers <<<mesh>>> through the tilinglinalg MLIR pipeline into host.cc (device init, DMA BDs, locks, launch) and routing.cc (stream switches). Compared with aiehlc's build of test_conv2d.cc: kernel.cc, routing.cc, aieml.bcf/.prx are byte-identical; host.cc only lacks test_conv2d's main().

10. The packed-call entry appended to aie/host.cc

The library speaks conv2d_stem_nchwc(ifm, wts, qp, ofm); the graph speaks the TVM packed ABI with 9 tensors. aie_stem_lib._ENTRY_TMPL bridges them and is appended to host.cc (a sibling file would be dropped — hostcompile.sh compiles a fixed source set), then hostcompile.sh re-archives libconv2dstem.a. Condensed:

extern "C" int32_t aie_tvmgen_…_1a1eefcf0256215e_(void *args, int32_t *type_codes,
        int32_t num_args, void *out_ret_value, int32_t *out_ret_tcode, void *rh) {
    printf("[aie-offload] layer 01 …: ENTER aiehlc conv2dstem (conv2d_stem_nchwc on the AIE mesh)\n");
    /* TVMValue.v_handle = DLTensor*, whose first field is data (byte_offset is 0) */
    const int8_t  *ifm  = data(args,0);   /* int8  [1,1,230,230,3] zp-padded  */
    const int8_t  *wts  = data(args,1);   /* int8  [16,1,7,7,3,4]  OIHW3i4o   */
    const int32_t *zp_a = data(args,2), *bias = data(args,3), *zp_b = data(args,4),
                  *mult = data(args,5), *unused = data(args,6), *shift = data(args,7);
    uint8_t       *ofm  = data(args,8);   /* uint8 [1,16,112,112,4] NCHW4c    */
    static conv2dstem_qparam qp[64];
    for (oc = 0; oc < 64; oc++) {          /* = test_conv2d.cc:fold_qparams()  */
        if (zp_b[oc] || unused[oc]) return CONV2DSTEM_ERR_BAD_QPARAM;   /* refuse, don't guess */
        qp[oc] = (conv2dstem_qparam){ bias[oc], zp_a[oc], mult[oc], shift[oc] };
    }
    int rc = conv2d_stem_nchwc(ifm, wts, qp, ofm);
    printf("[aie-offload] layer 01: EXIT rc=%d, ofm[0..7]= …, hash=%08x\n", rc, h);
    return rc == 0 ? 0 : -1;
}

The hash is h = h·31 + byte over all output bytes — compute the same over TVM's layer-01 output and you have a one-line bit-exactness check (§13).

11. graph_driver.c — TVM's graph executor as straight C

arm_build.generate_driver replaces TVM's C++ runtime with generated C:

  • one static buffer per storage id (TVM already did liveness and aliasing: 165 buffers, 14.3 MB);
  • graph_init() points parameter tensors into the linked weights.bin;
  • graph_run(): for each of the 41 nodes, fill args[] with &tensors[i] and call the kernel.

For every symbol in arm_build.aie_entries(layers/) — read from partition.json, and only if the archive exists and its host.cc defines the entry — the call is emitted twice:

    args[0].v_handle = &tensors[1];   …   args[8].v_handle = &tensors[9];
#ifdef GRAPH_AIE_OFFLOAD
    aie_tvmgen_default_fused_nn_contrib_conv2d_NCHWc_…_1a1eefcf0256215e_(args, codes, 9, 0, 0, 0);
#else
    tvmgen_default_fused_nn_contrib_conv2d_NCHWc_…_1a1eefcf0256215e_(args, codes, 9, 0, 0, 0);
#endif

Same arguments, same buffers, different implementation. Under make TRACE=1 the lines around each call dump inputs/outputs (layeriohex/), which is how test_conv2d.cc got its real data.

Do not hand-edit graph_driver.c — the next deploy_flow run overwrites it. Change arm_build.generate_driver / _trace_lines instead.

12. Makefile, link, main.elf

arm_build.write_makefile writes arm_build/Makefile; Python only generates, make builds, so you can re-run it by hand.

LAYER_SRCS      := $(wildcard layers/*/*.c)        → liblayers.a  (33 CPU kernels)
AIE_LAYER_LIBS  := $(wildcard layers/*/aie/build/*.a)              (libconv2dstem.a)

    $(CC) … $(AIE_LDIRS) -L$(BSP)/lib  -Wl,--start-group,-lm,-lxil,…,-lxaienginea78,-lstdc++,--end-group
  • aielib/ stages the AIE driver (libxaienginea78.a, from thirdparty/alib/lib, which every aiehlc run regenerates) and a copy of the BSP's libxil.a with its 62 stale xaie* members stripped — otherwise multiple definition of XAie_UpdateNpiAddr. AIE_LDIRS must come before the BSP.
  • ld only pulls archive members that resolve an undefined symbol, so the CPU kernel of layer 01 is still in liblayers.a but unused in main.elf.
  • main.c: graph_init → graph_run (timed) → top-5 → device_teardown done.
  • make local builds main_local.elf with host gcc (-D__AIESIM__ -std=gnu11), no AIE, no macro → the CPU reference.

15. Where to optimize

  • Measure first. Board: inference 2477.876 ms for the whole network with layer 01 on the AIE (the other 40 calls are scalar C on the A78). Per-layer timing: wrap the call in graph_driver.c's generator with aie_timer.h, or print in the entry.
  • Per-call fixed cost in the entry path: conv2d_stem_nchwc calls aieSetDevice(0) and partitions the mesh every call; staging scatters the whole 230×230 input each call; weights are repacked only when the pointer changes (g_wts_src). For repeated inference, hoist init/partition out of the call.
  • Host↔AIE register cost: ~372 ns per XAie_Write32 vs ~2.9 ns via control packets (doc/performance/register_write_cost.md) — BD/lock setup dominates small layers.
  • More layers: every other conv still uses the placeholder body. A second hand kernel = a new matches_* + build_*_layer in the style of aie_stem_lib, or fix the generic kernels.conv_bn_body to int32 + real requant.
  • Layout copies: stage_ifm_prepadded and collect_ofm_nchwc are host-side repacks around the AIE; consuming NCHW4c directly in the GemmSpace would remove them.
  • The 24 Invalid column errors come from core-processor-bus config of tiles outside the opened partition; worth fixing before timing small effects.

16. Hand-write a layer yourself

Everything the flow automates, as manual steps — for bring-up of a new kernel or when you need to bisect the flow.

Automated version: steps 2–6 below are what the user-kernel interface does for you — write AIEK_ENTRY + AIEK_SPEC (include/aie_user_kernel.h) and an x86 AIEK_REFERENCE, then python3 -m frontend.tvmrelay.aiekernel check|offload or deploy_flow.py --aie-kernel SRC[@layers]: lint, layer detection, calibration against TVM's kernel, whole-network x86 emulation, aiehlc build, generated packed-call adapter and driver swap. See doc/tutorial_userkernel.md.
  1. Get the layer's real data. make -C worklocal/tvmrelay_deploy/arm_build clean-local && make … local TRACE=1, run ./main_local.elf in arm_build/ → layeriohex/lNN_<op>_in.h / _out.h (all inputs incl. named params, and the golden output). network.md tells you each argument's dtype, shape and role.
  2. Write the kernel library as an aiehlc source with no main() (template: conv2dstem.cc): a __global__ kernel, a launch kernel<<<mesh>>>, host staging, and a C-callable entry taking TVM's layouts.
  3. Prove it standalone with a test entry file (test_conv2d.cc pattern: #include "mykernel.cc" + the dump headers + golden compare), built by source script/aiehlc.sh --aie-version 5 --runtime-source-file …/test_mykernel.cc and run with apppaltest.py. Do not continue until it prints a bit-exact PASS.
  4. Build the library into the layer: run aiehlc on the library source in a scratch dir, copy aout/worklocal/ to layers/NN_…/aie/.
  5. Add the packed entry to aie/host.cc (§10 template): unpack args[i], convert params, call your entry, print ENTER/EXIT. Re-archive: cd layers/NN_…/aie && bash $REPO/script/hostcompile.sh --aie-version 5.
  6. Swap the call: add entry/replaces/archive/target: aie to that layer in partition.json and re-run stage 6 (python3 -m frontend.tvmrelay.arm_build or the flow), or hand-patch a copy of graph_driver.c with the #ifdef and add -DGRAPH_AIE_OFFLOAD.
  7. Link and compare: make → main.elf; make local → main_local.elf; board top-5 must equal local, and your EXIT hash must equal the hash of _out.h.
Invariants that fail silently (wrong pixels, no error)
  • Pad with the zero-point, not 0 (stem: −15 in int8 = 113 − 128).
  • Accumulate in int32 (stem peak |acc| = 1,023,225).
  • Match TVM's packed layouts (OIHW3i4o weights, NCHW4c output) or repack explicitly.
  • TVM subtracts two zero-point terms; folding to one is valid only if the second is 0 — check it, as fold_qparams does.
  • Requant rounding is (x·m + 2^(s+30)) >> (s+31) in int64 (half-up).
  • Read int32 params from byte arrays by assembling bytes — an unaligned cast faults on the A78.
